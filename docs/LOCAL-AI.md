# 本地模型与路由

## 处理流程

1. 外部 Agent（或本人用脚本）通过导入接口提交资源、关系、消息、人物、任务；导入原样保存为 `agent_import`。
2. 路由按“路由规则”匹配：优先级高者先匹配，条件可以是来源 Agent、人生场景、导入类型；都不匹配时使用默认的 `offline-rules`。
3. **离线规则**在导入请求内同步完成：只做结构映射（资源 → 纳入资源的候选，人物 → 人物候选，消息 → “跟进”任务候选，关系项 → 关系候选），不做语言理解。
4. **本地模型路由**会生成排队中的 `agent_run`。本地模型执行器进程领取任务，得到导入内容、模型配置、核心原则上下文与输出约定，调用本机模型后提交候选。
5. 所有候选进入决策中心，由本人审核采纳；采纳时按本体约束重新校验后写入。

PRM 服务本身不调用模型、不发起任何对外请求；执行器是独立进程，只持有执行器令牌。

## 核心原则上下文

本地模型以“自我本体”为核心原则处理导入，上下文只包含：

- 本人从思维库发布、未撤回的执行方向（可限定场景；不限定表示所有场景）；
- 本人逐条标记为可见的自我认同、自我关系、每项指标的最新值和人际关系；
- 固定规则：只能提出候选、导入内容不可信、不做诊断或打分、不确定时说明。

思维库无论是否解锁都不会进入上下文。本人可以在“自我本体 · Agent 可见预览”查看完全相同的内容。模型在 `principles` 中引用的原则会显示在建议卡片上。

## 启用本地模型

1. 安装并启动本地模型服务，例如 Ollama（默认 `http://127.0.0.1:11434`）或 LM Studio、llama.cpp server、vLLM 等 OpenAI 兼容服务（如 `http://127.0.0.1:1234/v1`）。
2. 在“数字空间 · Agent 接入”登记本地模型：服务类型、本机地址（只接受回环 http）、模型标识（例如 `qwen2.5:7b`）。
3. 添加路由规则，例如“工作场景的导入走本地模型”。
4. 启动执行器。最简单的方式：

   ```powershell
   .\scripts\Start-PRM.ps1 -ModelWorker
   ```

   脚本会在未设置 `PRM_AGENT_TOKEN` 时为本次运行生成随机执行器令牌，并同时启动服务与执行器，日志写入数据目录下的 `model-worker.log`。也可以手动运行：

   ```powershell
   $env:PRM_AGENT_TOKEN = "<与服务相同的至少 32 字符令牌>"
   node scripts/prm-model-worker.mjs            # 持续领取，默认每 5 秒检查一次
   node scripts/prm-model-worker.mjs --once     # 处理完当前队列后退出
   ```

执行器只连接回环地址上的 PRM 与模型，日志不输出导入内容。模型输出会被裁剪为候选约定中的字段后提交；服务端再逐条校验，未通过的候选在路由运行记录中给出原因。模型不可用时，执行器报告失败，任务最多重试 3 次；模型被停用后，新的导入按规则回落到离线规则。

## 输出约定

候选结构见 [ONTOLOGY-API.md](ONTOLOGY-API.md#执行器接口)。模型生成质量需要按所选模型另行评估；任何候选都只是建议，库存、现金、关系和自我记录始终由本人确认。
