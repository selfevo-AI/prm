# 核心精神权限与安全

## 身份与授权

本项目仍是本机、单所有者工作区。所有者通过账户口令建立会话，同时把设备 Ed25519 公钥绑定到该会话。除认证入口和认证状态外，所有本人 API 请求都同时验证 HttpOnly 会话和设备签名。口令登录可绑定新的设备密钥；这里不是硬件多因素认证，也没有声称验证物理操作人的身份。

| 操作 | 本人 | 只读接收者 | 本地模型执行器 | 外部 Agent |
| --- | --- | --- | --- | --- |
| 查看业务工作区 / 导出 / 自我本体 | 会话 + 签名 | 拒绝 | 拒绝 | 拒绝 |
| 解锁核心精神 | 会话 + 签名 + 口令 | 拒绝 | 拒绝 | 拒绝 |
| 新建、修改、复核、发布精神条目 | 会话 + 签名 + 口令 + 明确确认 + 版本检查 | 拒绝 | 拒绝 | 拒绝 |
| 创建只读授权 | 解锁中 + 会话 + 签名 + 口令 | 拒绝 | 拒绝 | 拒绝 |
| 撤销只读授权 | 会话 + 签名 | 拒绝 | 拒绝 | 拒绝 |
| 读取授权条目 | 解锁后读取自己的完整库 | 有效授权 + 接收者签名 + 本人当前已解锁 | 拒绝 | 拒绝 |
| 签发 / 撤销外部 Agent 令牌，配置模型与路由 | 会话 + 签名 | 拒绝 | 拒绝 | 拒绝 |
| 导入资源、关系、消息（待审） | 不适用 | 拒绝 | 拒绝 | 连接令牌，仅导入与查询自己导入的状态 |
| 领取路由任务、读取核心原则上下文、提交候选 | 通过本人工作流程 | 拒绝 | `PRM_AGENT_TOKEN`，仅 `/api/agent/*` | 拒绝 |
| 采纳建议、写入本体、库存、现金、关系 | 会话 + 签名 + 版本检查 | 拒绝 | 拒绝 | 拒绝 |

授权只支持 `read`，没有可提升为 `write` 的输入字段。授权绑定接收者公钥和显式条目 ID 列表，有效期为 1 分钟至 24 小时，返回当前条目，不返回历史版本。权限撤销和读取在同一应用锁内重新检查；过期授权也在读取时再次检查。锁定、退出、会话过期或服务重启会停止解密，重新本人解锁后尚未过期的授权才能继续读取。

这意味着授权适合本人解锁期间在后台运行的本地读取程序；切换到其他窗口可能触发本人视图自动锁定，此时只读页面会显示“本人尚未解锁”。它不是持续在线的远程分享服务。撤销无法收回接收者已经保存的内容。

普通 Agent 凭证不能读取核心精神。执行器与外部 Agent 使用各自独立的 Bearer 令牌，只能调用固定形状的接口；接收者签名授权是另一条独立权限路径。

## Agent 凭证、路由与本地模型

- **两类 Bearer 身份**。`PRM_AGENT_TOKEN`（至少 32 字符，经环境变量交给服务和执行器进程）只代表本机的本地模型执行器；中间件把它限制在 `/api/agent/*`，处理函数再次校验身份。外部 Agent 使用本人在界面签发的连接令牌（`prm_` 前缀、32 字节随机数），数据库只保存其 SHA-256，令牌只在签发时显示一次，可随时撤销；它只能访问导入接口和查询自己导入的状态，看不到处理结果、本人数据或其他 Agent 的导入。
- **导入是不可信数据**。导入原样保存为 `agent_import`，不会直接创建资源、关系、任务、库存或现金；离线规则只做结构映射，不做语言理解。所有输出都是待审候选，由本人采纳后才按本体约束写入，并以 `derived_from` 留下来源。
- **核心原则上下文**。路由交给本地模型的只有：本人发布且未撤回的执行方向（可按场景限定）、本人逐条标记为可见的自我认同、自我关系、最新指标和人际关系，以及固定规则。思维库无论是否解锁都不在其中；本人可以在“自我本体 · Agent 可见预览”看到完整内容。
- **服务不对外发起请求**。本地模型地址只能是 `http://` 的 127.0.0.1、localhost 或 [::1]，服务端与执行器各自校验一次；调用模型的是独立的执行器进程，PRM 服务进程本身仍然只连接本机 PostgreSQL。
- **执行器租约**。执行器领取任务时获得随机租约（300 秒），提交结果或失败报告必须携带当前租约，过期或被重新领取后旧租约失效；同一任务最多尝试 3 次。模型输出按 `prm-candidates-v1` 严格校验，含未知字段的整体拒绝（422），语义不合法的单条候选被拒绝并返回原因。
- **候选的能力上限**。候选只能建议任务、可建议类型的实体（资源、库位、供应商、知识、人物）和可建议的关系（关联、使用、供应、存放于、落实）。不能建议现金、库存流水、思维条目、自我记录、执行方向或任何权限。

## 非对称请求验证

采用标准 Ed25519 签名、SHA-256 摘要和 Web Crypto，不把“Web4”作为自定义密码算法或区块链依赖。签名负责身份持有证明和请求完整性；内容加密由下述 AEAD 负责。

浏览器生成不可导出的私钥，以 CryptoKey 对象存入 IndexedDB，服务端只接收公钥。删除浏览器站点数据会丢失该设备密钥，需重新使用账户口令登录；接收者需要重新申请授权。不要把 IndexedDB 中不可导出等同于抵抗同源恶意脚本：已控制的浏览器仍可调用签名能力。

请求头为 `X-PRM-Timestamp`（Unix 秒）、`X-PRM-Nonce`（至少 22 字符的随机 base64url）、`X-PRM-Signature`（base64url Ed25519 签名）。接收者额外携带 `X-PRM-Grant`。签名消息是 UTF-8 字节，下面每行之间为单个 LF，末尾没有换行：

```text
PRM-REQUEST-V1
<HTTP method>
<path including query>
<timestamp>
<nonce>
<base64url(SHA256(exact request body bytes))>
```

GET 空正文也计算 SHA-256。服务器允许时间偏差不超过 60 秒，使用严格签名校验，拒绝弱公钥。已消费随机数按公钥在 PostgreSQL 中唯一保存至少 125 秒，跨服务重启继续阻止有效时间窗内的重放。签名绑定请求正文、路径、查询参数和方法，不能转用于别的操作。

## 数据加密与 PostgreSQL

- 账户口令使用 Argon2id 验证；核心精神密钥由独立随机盐和 Argon2id 派生。
- 思维快照使用 XChaCha20-Poly1305，每次写入新的随机 nonce，AAD 为 `prm:mental-vault:v1`。私密标题、正文、历史都在密文中。
- 密钥及序列化明文使用 Zeroizing；显示和处理期间仍有内存明文。
- PostgreSQL `vault` 表保存密文。业务实体、账户验证哈希、授权标签、公钥、条目 ID、到期时间和审计元数据不做整体加密。审计不保存精神正文和私钥。
- 思维修改与审计写入使用同一 PostgreSQL 事务，失败一起回滚。审计表拒绝 UPDATE、DELETE、TRUNCATE。
- 应用使用非超级用户数据库角色。应用与数据库管理员拥有不同边界：数据库所有者或管理员仍能修改表结构，审计触发器不是外部不可篡改存证。
- 默认工作区 schema 是规范化数据目录路径的 SHA-256 前 12 字节，格式 `prm_<hex>`；可用 `PRM_DATABASE_SCHEMA=prm_main` 显式指定。迁移或备份恢复到其他目录时必须沿用原 schema，避免连接到新空工作区。
- 进程文件锁和 PostgreSQL advisory lock 阻止同一工作区被两个服务同时打开。数据库语句和锁等待分别限制为 10 秒和 5 秒。
- 当前数据库连接只允许显式环回主机，使用 SCRAM 认证；不接受远端明文 PostgreSQL。远程部署需另行接入 TLS、可信域名和部署认证配置。

## 会话、HTTP 与资源边界

会话 cookie 为 HttpOnly、SameSite=Strict。空闲 15 分钟、绝对 8 小时失效，重新登录撤销旧会话。本人解锁只保留 5 分钟，服务端定时清除过期密钥；前端离开思维页面或窗口失焦时主动锁定。只读页面也在失焦和每分钟清空已显示内容。

HTTP 仅监听 127.0.0.1；检查 Host、Origin 和修改请求自定义头，不启用 CORS。包括错误在内的响应添加 no-store、CSP、禁止嵌套、禁止 MIME 嗅探等头。正文最大 128 KiB。连续 5 次口令失败暂停验证 30 秒。

受信任本机 OS、应用二进制、浏览器和密码学库是运行前提。本实现不提供硬件密钥保护、硬件身份验证、恶意管理员防护、设备证明、远程 HTTPS 服务或密钥找回后门。

## SQLite 迁移与备份恢复

运行库已经改为 PostgreSQL。首次启动空工作区时，如数据目录有旧 `operations.sqlite3` 和 `mental-vault.sqlite3`，以只读方式导入账户、业务记录、关系、审计及完整精神密文；在单个 PostgreSQL 事务中提交。导入失败回滚，原文件不改写。成功后有 `database.migrated` 审计事件，再次启动不重复导入。旧文件只保留作原始备份，不再接收更新。

界面的业务 JSON 导出不含精神库，不是完整恢复备份。完整备份应使用 PostgreSQL `pg_dump` 自定义格式，包含工作区 schema（或专用数据库整个备份）。保存使用的 `PRM_DATABASE_SCHEMA` / 原目录标识，保护数据库凭证，并保存账户口令。示例通过环境变量设置 PGHOST、PGPORT、PGUSER、PGDATABASE、PGPASSWORD 后执行：

```powershell
pg_dump -Fc -f prm-backup.dump
# 恢复到预先创建的空数据库，避免覆盖正在使用的数据库：
pg_restore --no-owner --no-privileges -d prm_restored prm-backup.dump
```

恢复后的应用需连接新数据库并使用备份中的原 schema。测试原口令可以解锁后再切换使用。浏览器私钥不在数据库备份中；本人可以重新口令登录绑定设备，接收者需要保存自己的浏览器设备资料或重新申请授权。当前未提供口令轮换或恢复密钥。
